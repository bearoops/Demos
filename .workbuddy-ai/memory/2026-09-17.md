# 2026-09-17

## TestWidget：从网络下载多张图片并显示

工程：SwiftUIDemo（iOS 26.2 / Xcode 26.2），`TestWidgetExtension` 用
`PBXFileSystemSynchronizedRootGroup` 同步 `TestWidget/` 目录，新增 .swift 文件自动入 target，无需改 pbxproj。

### 改动

新增：
- `TestWidget/ImageLoader.swift` — 并发下载（TaskGroup + 12s deadline）+ ImageIO 降采样 + NSCache/URLCache
- `TestWidget/ImageSource.swift` — AppEnum：picsum / picsum 黑白 / dummyimage
- `TestWidget/WidgetImage.swift` — Entry 用的图片模型、按 WidgetFamily 的网格布局参数、预览假数据

改写：
- `TestWidget/TestWidget.swift` — Provider 在 timeline 里下载图片塞进 Entry；GeometryReader 网格铺满；失败格显示占位图；右下角「换一批」按钮
- `TestWidget/AppIntent.swift` — 配置项改为「图片来源 + 图片数量」；新增 RefreshImagesIntent + WidgetRefreshToken

### 关键结论

- Widget 视图层不能用 `AsyncImage`（静态渲染），必须在 TimelineProvider 里下载解码后放进 TimelineEntry。
- Widget 进程内存约 30MB，必须用 ImageIO 降采样，按单元格 2x 请求即可。
- 图片源用 `https://picsum.photos/seed/{seed}/{w}/{h}` 和 `https://dummyimage.com/{w}x{h}/{hex}/ffffff&text=n`，均验证 200。
- 「换一批」用 UserDefaults 自增 token 拼进 URL 绕缓存；Intent 与 Provider 同在扩展进程，无需 App Group。

### 环境注意

- 本机默认 DerivedData 被沙箱拦截，必须加 `-derivedDataPath /tmp/<name>-dd`，且构建命令需禁用沙箱，否则 `#Preview` 宏插件报 malformed response（与代码无关）。
- `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY = YES` → 用 `Button(intent:)` 必须显式 `import AppIntents`。
- `@Parameter` 的 `inclusiveRange` 要写元组 `(1, 9)`，不能写 `1...9`。

两个 scheme（SwiftUIDemo / TestWidgetExtension）均已编译通过。

### 实测数据（macOS 上用真实 ImageSource.swift + 同款 ImageIO 参数跑通）

3 个来源 × 3 种尺寸全部 100% 成功，解码尺寸与请求尺寸完全一致：

| 场景 | 内存 | 耗时 |
|---|---|---|
| 小号 4 张 152x152 | 0.35 MB | ~2.1s（冷） |
| 中号 6 张 220x132 | 0.66 MB | ~1.8s |
| 大号 9 张 220x220 | 1.66 MB | ~0.9s（热） |

结论：最大场景仅 1.66MB，远低于 Widget 30MB 上限；耗时也远在时间线预算内。
灰度图解码后是 1 字节/像素（9 张仅 0.42MB），比彩色省 4 倍。
